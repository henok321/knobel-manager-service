# Wire field rename: `*ID` → `*Id`

**Spec proposal:** `/Users/brinkmann/git/private/knobel-manager-service/docs/superpowers/proposals/id-rename.md`
**Date:** 2026-09-21
**Breaking wire change** (both server & client updated in lockstep, same PR/commit pair).

## Goal

Rename the six ID wire field names in the OpenAPI spec so generated TS uses `gameId` style:
`gameID`→`gameId`, `teamID`→`teamId`, `playerID`→`playerId`, `roundID`→`roundId`, `tableID`→`tableId`, `entityID`→`entityId`.

Wire names are just strings — Go keeps its `GameID`-style identifiers in hand-written domain code via json tags; only generated-api field accessors change (`GameID`→`GameId` in `api.*` structs).

## Verified fallout surface

- `openapi/openapi.yaml`: 54 match lines — properties, `required` lists, path param names (`{gameID}` placeholders, `- name: gameID`), error strings ("Invalid gameID"), examples. Uniform token replace covers all.
- Hand-written Go fallout: ONLY `api/handlers/converters.go`, 8 refs: `TeamId` (L14), `PlayerId` (L21), `TableId` (L23), `RoundId` (L30), `GameId` (L55, 73, 94), `EntityId` (~L125). Left side only; right-side entity fields stay `GameID`.
- Handler method signatures implementing generated `ServerInterface`: unaffected (Go param names don't affect interface satisfaction).
- `pkg/entity`, `pkg/game`, `pkg/audit`: hand-written domain code, untouched.
- Integration tests: no `api.X` references; `auditRow` in `audit_test.go` is a local DB struct — untouched.
- Integration test wire keys: 23 string occurrences in 5 `.go` files (`scores_test.go` 12, `games_test.go` 4, `teams_test.go` 3, `players_test.go` 2, `audit_test.go` 2) + ~270 occurrences across 9 fixture JSONs in `integrationtests/test_data/`.
